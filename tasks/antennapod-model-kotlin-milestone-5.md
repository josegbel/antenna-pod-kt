## Research
_Last updated by: legacy-android-researcher | 2026-07-24_

### Summary
The `:model` module is a plain, KMP-portability-minded data module carrying AntennaPod's core domain types. Milestones 1–4 (merged to `develop`) converted the enum/POJO and framework-coupled-enum tiers; exactly **7 `.java` files remain**: `DownloadRequest`, `EmbeddedChapterImage`, `FeedMedia`, `FeedPreferences`, `SubscriptionsFilter`, `Playable` (interface), `RemoteMedia`. Re-verifying the tiering carried forward from Milestone 4 against live code, it still holds with one refinement noted below: three files are **Tier B** (`android.text.TextUtils`-coupled only — a pure-JVM guard swap makes them bare-JVM testable without Robolectric): `EmbeddedChapterImage`, `SubscriptionsFilter`, `FeedPreferences`. Four are **Tier C** (`android.os.Parcel`/`Parcelable` marshalling, not bare-JVM testable without Robolectric or an instrumented `androidTest`): `DownloadRequest`, `FeedMedia`, `RemoteMedia`, and `Playable` (the interface both `FeedMedia` and `RemoteMedia` implement, which itself `extends Parcelable, Serializable`).

This milestone's `kotlin`-track work is a same-shape continuation: pick the next reviewable batch (Milestone 4 was 4 files), write Java characterization tests **first** for the currently-untested behavior, then J2K-convert while preserving public API and exact runtime behavior. The recommended batch is the **three Tier B files** (`EmbeddedChapterImage`, `SubscriptionsFilter`, `FeedPreferences`), all of which have **zero existing test coverage** and are bare-JVM testable after the `TextUtils` guard swap — keeping `:model` Robolectric-free per José's 2026-07-21 call. Whether any Tier C file (Parcelable) folds into this milestone remains an **open question for José** (Robolectric vs. instrumented `androidTest` vs. verification-by-inspection for Parcelable characterization) and is left to the planner + José, not assumed in scope here.

### Constraints & Risks
- **`TextUtils.split` empty-string trap (CRITICAL, live-exercised).** `TextUtils.split("", ",")` returns a **zero-length** array, so `new SubscriptionsFilter("").isEnabled()` is `false`. A naive J2K/guard swap to Kotlin `"".split(",")` returns `[""]` (length 1), flipping `isEnabled()` to `true` and corrupting default filter state — and `new SubscriptionsFilter("")` is called live (DBReader.java:660, SubscriptionFragment.java:369). The guard swap must reproduce AOSP `TextUtils.split` semantics (empty input → empty array; limit `-1` otherwise), and a characterization test must pin the empty-string case before conversion.
- **`serialize()` round-trip stability.** `SubscriptionsFilter.serialize()` (`TextUtils.join`) feeds persisted `UserPreferences` state; the guard-swapped join must produce byte-identical output (comma-joined, no trailing separator) or previously-saved filters mis-parse.
- **`FeedPreferences` `Serializable` with no `serialVersionUID`.** The class declares none (nor does `Playable`/`RemoteMedia`). It's `Serializable` transitively via `Feed`. Converting to Kotlin can change the compiler-computed default `serialVersionUID` (field/synthetic layout), which would break deserialization of any object graph persisted across the change. Planner must decide whether to pin an explicit `serialVersionUID` and confirm whether `FeedPreferences`/`Feed` is ever Java-serialized to durable storage vs. only intra-process.
- **`FeedPreferences` enum API preservation.** 4 nested enums expose `public final int code` and static `fromCode`/`fromInteger`/`fromBoolean` with specific default fallbacks (e.g. `AutoDeleteAction.fromCode` → `NEVER`, `NewEpisodesAction` → `ADD_TO_INBOX`, `SkipSilence`/`AutoDownloadSetting` → `GLOBAL`). Use `@JvmField`/`@JvmStatic`/`const val` per established convention; the fallback branches must be characterized, not just the hits. Also `getFeedSkipSilence()` returns `GLOBAL` whenever `feedPlaybackSpeed == SPEED_USE_GLOBAL` regardless of the stored value (FeedPreferences.java:298-303) — a behavioral branch easy to lose.
- **`EmbeddedChapterImage` regex + `getModelFor` return polymorphism.** Constructor throws `IllegalArgumentException` on a non-matching URL; `getModelFor` returns `Object` (either the instance or the raw `String`). Preserve the `Object` return type and the throw; `makeUrl`↔constructor must round-trip. `equals` via `TextUtils.equals` is null-tolerant — the stdlib replacement (`==`/`Objects.equals`) must preserve that.
- **API-preservation convention (re-verified as still applicable):** avoid `data class` where reference/field-selective equality is relied upon — notably `FeedMedia`/`RemoteMedia` cross-type `equals` (FeedMedia.java:509-511, RemoteMedia.java:276-287) and `SubscriptionsFilter`/`DownloadRequest` hand-written semantics — but these are Tier C / not in the recommended batch. The Tier B files have simpler equality (`EmbeddedChapterImage` by url; `SubscriptionsFilter` has none; `FeedPreferences` has none) so `data class` is still likely wrong-fit but low-risk.

## Plan
_Last updated by: legacy-android-planner | 2026-07-24 (revision)_

> **Revision note (red-team loop 1):** This Plan was revised to address the two findings in the "Red-Team Verdict — Plan" CHALLENGE (loop 1) below, without re-scoping the 3-file Tier B batch (the split-fix design and Acceptance Criteria wording were confirmed sound): (1) **MAJOR** — the `textUtilsSplit` helper must be declared in `SubscriptionsFilter`'s `companion object` (alongside `divider`), not as an instance member. Red-team compiled the instance-member shape through `:model:compileDebugKotlin` and it fails (`Cannot access '<this>' before the instance has been initialized`) — a Kotlin rule that forbids referencing an instance member in a constructor-delegation argument list; companion-object placement compiles clean. The Resolved Decisions snippet and Step 4 now specify companion-object placement explicitly. (2) **MINOR** — Step 3's `SubscriptionsFilter` test list now includes a divider-only-string case (`onlyDividerConstructorNoPropertiesMatch`) for branch-trace completeness. Red-team hand-traced this branch and found no divergence risk (the historical bug is specific to the empty-string branch, not the all-divider branch), so no equivalence claim rests on it — it is added only to match the "trace every branch" rigor of this milestone's review and the Milestone 4 precedent.

### Objective
Continue the `:model` `kotlin`-track case study (Milestone 5) by converting the **Tier B `TextUtils`-coupled tier** — `EmbeddedChapterImage`, `SubscriptionsFilter`, `FeedPreferences` — from Java to behaviorally-equivalent Kotlin, preserving every downstream-visible Java API (public fields, `@JvmField` enum `code` fields, `@JvmStatic` factory methods, JavaBean accessors, `Serializable` contract), replacing each `android.text.TextUtils.*` call with a JDK/Kotlin-stdlib equivalent that reproduces AOSP semantics **bit-for-bit** (especially the `TextUtils.split` empty-string trap), and keeping `:model` Robolectric-free. `kotlin` is the only requested track and has no unmet prerequisites.

### Resolved Decisions

- **Unknown — batch size / `FeedPreferences` solo-vs-paired (RESOLVED by planner: keep all 3 Tier B files in one milestone; `FeedPreferences` converts SOLO in its own single-file diff — not paired, not split into its own milestone).** All three Tier B files are the recommended batch, mirroring Milestone 4's 4-file reviewability. Unlike Milestone 4's `Feed`+`FeedItem` (which shared a mutual `List<FeedItem>`↔`transient Feed` cycle and *had* to convert together), these three are **not mutually coupled**: `EmbeddedChapterImage` depends only on `Playable` (Tier C, untouched); `SubscriptionsFilter` is standalone; `FeedPreferences` depends only on `FeedFilter`/`VolumeAdaptionSetting` (already Kotlin, untouched). Therefore each converts as an **independent one-file diff**, which is the reviewability unit — there is no diff-size reason to combine any two, and `FeedPreferences` (324 LOC, 4 nested enums) is heavy enough that pairing it with another file would make one diff too large to review cleanly. Net step count is the natural per-file (characterization-then-convert) pairing: 3 test steps + 3 conversion steps + 1 README = **7 steps**, same shape as Milestone 4. Order is simplest-first: `EmbeddedChapterImage` (no persistence surface), then `SubscriptionsFilter` (the split trap), then `FeedPreferences` (heaviest).
- **Unknown — `FeedPreferences` `serialVersionUID` (RESOLVED by planner: add `private const val serialVersionUID = 1L`).** `FeedPreferences implements Serializable` with no explicit UID today, so its runtime UID is the JVM-computed hash of the current Java class shape; a J2K conversion changes that shape and therefore the implicit UID. Decision: add `private const val serialVersionUID = 1L` in the `companion object`, matching the module precedent (`FeedItemFilter.kt`, `DownloadResult.kt`, and — from Milestone 4 — `Feed.kt`/`FeedItem.kt`/`FeedFunding.kt`). Reasoning: (1) consistency with every `Serializable` class already converted in this module; (2) `FeedPreferences` is `Serializable` transitively via `Feed` (which already carries `serialVersionUID = 1L`), and the only serialization path in the repo is `Bundle.putSerializable`/Intent extras — **intra-session only** (Fragment args / `savedInstanceState`, never persisted to disk/network; no `ObjectOutputStream`/`writeObject`/`readObject` anywhere in the repo per Milestone 3–4 research), so an implicit-UID change cannot break a real user across an app upgrade; (3) `TagSettingsDialog.java` serializes `ArrayList<FeedPreferences>` via `Bundle.putSerializable` (Milestone 4 research, live) — so the UID must be applied deliberately, not left compiler-generated. Recorded explicitly per the researcher's instruction, even though the call is straightforward and consistent with Milestone 4.
- **`TextUtils.split` empty-string trap (RESOLVED by planner — CRITICAL, live-exercised; the fix is a faithful transcription of AOSP `TextUtils.split`, NOT Kotlin's `String.split`).** AOSP `android.text.TextUtils.split(String text, String expression)` is defined as: `if (text.length() == 0) return EMPTY_STRING_ARRAY; else return text.split(expression, -1);` (source: AOSP `frameworks/base/core/java/android/text/TextUtils.java`). Two properties matter: (a) **empty input → zero-length array**; (b) non-empty input is split by `text.split(expression, -1)`, i.e. `Pattern.compile(expression).split(text, -1)` — **limit `-1` keeps trailing empty tokens**. The naive J2K/guard swap to Kotlin `properties.split(divider)` diverges on (a): Kotlin's `"".split(",")` returns `[""]` (length 1), flipping `new SubscriptionsFilter("").isEnabled()` from `false` to `true` and corrupting default filter state — and `new SubscriptionsFilter("")` is called live (`DBReader.java:660`, `SubscriptionFragment.java:369`). (Note: for **non-empty** input Kotlin's literal `.split(",")` happens to also keep trailing empties, so it matches on (b) — but the empty-input divergence alone is fatal, and relying on that partial coincidence is exactly the accidental-equivalence the pipeline exists not to depend on.)
  - **Decision:** replace the `TextUtils.split(properties, divider)` call in `SubscriptionsFilter`'s `String` constructor with a helper that transcribes AOSP's body exactly, using direct `java.util.regex.Pattern` JDK interop (byte-for-byte identical to `text.split(expression, -1)`, which `String.split(String, int)` *is*). **This helper MUST be declared inside `SubscriptionsFilter`'s `companion object` (alongside `divider` and the 8 key constants), NOT as an instance-scope member** — the `String` constructor invokes it in its constructor-delegation argument list (`constructor(properties: String) : this(textUtilsSplit(properties))`), and Kotlin forbids referencing an instance member there because `this` is not yet initialized (`Cannot access '<this>' before the instance has been initialized`; red-team compiled both shapes through `:model:compileDebugKotlin` — the instance-member form fails, companion-object form compiles clean). Declare it as a companion-object function; the same constraint applies to anything else called from a constructor-delegation argument:
    ```kotlin
    companion object {
        private const val divider = ","
        // ... the 8 property-key const val constants ...

        // Reproduces AOSP TextUtils.split(text, expression) bit-for-bit:
        //   empty input -> zero-length array; otherwise Pattern.compile(expression).split(text, -1),
        //   where limit -1 KEEPS trailing empty tokens.
        // Do NOT replace with Kotlin's String.split(","): it returns [""] (length 1) for "",
        // which flips SubscriptionsFilter("").isEnabled() from false to true and corrupts default
        // filter state (new SubscriptionsFilter("") is live at DBReader:660 / SubscriptionFragment:369).
        // No test after this line can catch such a revert for the non-empty path (Kotlin split
        // matches there) — this comment + emptyStringConstructorIsNotEnabled are the regression guard.
        // MUST live in the companion object: it is called from the String constructor's
        // this(...) delegation, where an instance member cannot be referenced ('this' not yet initialized).
        private fun textUtilsSplit(text: String): Array<String> =
            if (text.isEmpty()) emptyArray() else Pattern.compile(divider).split(text, -1)
    }
    ```
    Do **NOT** use Kotlin's `String.split(String)` / `String.split(Regex)` / vararg `split` overloads for this call. (`divider = ","` is a literal with no regex metacharacter, so `Pattern.compile(divider)` is safe.)
  - **Also swap `TextUtils.join` (behavior-preserving, lower-risk):** `SubscriptionsFilter.serialize()`'s `TextUtils.join(divider, getValues())` → `getValues().joinToString(divider)` and `FeedPreferences.getTagsAsString()`'s `TextUtils.join(TAG_SEPARATOR, tags)` → `tags.joinToString(TAG_SEPARATOR)`. AOSP `TextUtils.join` returns `""` for an empty collection and comma/separator-joins with no trailing separator; Kotlin `joinToString` is byte-identical (empty → `""`, same element order for the `Iterable`/array, no trailing separator). `serialize()` round-trip stability is required (it feeds persisted `PREF_FILTER_FEED`) and is pinned by a characterization test.
  - **Non-negotiable ordering:** `SubscriptionsFilterTest.java` must pin the empty-string case (`emptyStringConstructorIsNotEnabled`, `emptyStringSerializeReturnsEmpty`) and the trailing-separator case, written and **passing against the live Java `SubscriptionsFilter` before any conversion** (Step 3). This mirrors the Milestone-4 `FeedFunding`/`String.split` trailing-token precedent (see that file's Plan/Red-Team sections): faithfulness is a property of construction (AOSP-source transcription) + JDK contract, not a claim that the test suite alone proves no-regression.
- **`TextUtils.equals` in `EmbeddedChapterImage` (RESOLVED by planner: replace with Kotlin `==`).** `equals()` uses `TextUtils.equals(imageUrl, that.imageUrl)`, which is null-tolerant (both null → true; one null → false; else `String.equals`). Kotlin's `==` compiles to a null-safe structural-equality check with **exactly** those semantics, so `imageUrl == that.imageUrl` is a faithful replacement. **Honest-coverage caveat (per José's standing unverifiable-equivalence policy, Milestone 4):** `imageUrl` is effectively non-null after construction (the constructor throws `IllegalArgumentException` unless the URL matches `EMBEDDED_IMAGE_MATCHER`, and `hashCode()` calls `imageUrl.hashCode()` unguarded), so the null-tolerant branch of `TextUtils.equals`/`==` is **not reachable** and therefore **cannot be pinned by a test**. Equivalence of the null branch rests on the Kotlin `==` language contract, not on test coverage — the Acceptance Criteria states this explicitly rather than overclaiming. Do **not** add null guards or nullability that the Java did not have (e.g. do not make `getModelFor` null-safe): if a null `imageUrl` reaches `isEmbeddedChapterImage`, current Java NPEs, and that behavior is preserved.
- **`FeedPreferences` enum API preservation (RESOLVED by planner: `@JvmField val code` + `@JvmStatic` factories, plain Kotlin `enum class`, fallbacks preserved verbatim).** The 4 nested enums expose `public final int code` accessed as a **field** by ~35 consumers (verified live: `SkipSilence.GLOBAL.code` at `PodDBAdapter.java:175`/`DBUpgrader.java:342`, `prefs.getAutoDownload().code` at `PodDBAdapter.java:498`, `.getAutoDeleteAction().code`, `.getNewEpisodesAction().code`, `NewEpisodesAction.ADD_TO_INBOX.code` at `UserPreferences.java:846`, etc.). A plain Kotlin enum constructor `val code: Int` would generate only `getCode()` and **break** this Java field access — so each enum must declare `enum class AutoDeleteAction(@JvmField val code: Int)` to preserve the public `int code` field. (This differs from the already-converted `VolumeAdaptionSetting.kt`, which used a `private val value` + `toInteger()` method because its callers use `fromInteger`/`toInteger`, not a public field — these enums' callers use the field directly, so `@JvmField` is required.) The static lookups become `@JvmStatic fun fromCode`/`fromInteger`/`fromBoolean` in each enum's `companion object`, with the **default fallbacks preserved verbatim and characterized**: `AutoDeleteAction.fromCode` → `NEVER`, `NewEpisodesAction.fromCode` → `ADD_TO_INBOX`, `SkipSilence.fromCode` → `GLOBAL`, `AutoDownloadSetting.fromInteger` → `GLOBAL`, `AutoDownloadSetting.fromBoolean(true/false)` → `ENABLED`/`DISABLED`. Enum constant `code` values are preserved exactly (e.g. `NewEpisodesAction.ADD_TO_QUEUE = 3`, `NOTHING = 2` — the non-sequential codes are pinned by test).
- **`FeedPreferences.getFeedSkipSilence()` GLOBAL branch (RESOLVED by planner: preserve verbatim).** `getFeedSkipSilence()` returns `SkipSilence.GLOBAL` whenever `feedPlaybackSpeed == SPEED_USE_GLOBAL` **regardless of the stored `feedSkipSilence`** (`FeedPreferences.java:298-303`), otherwise the stored value. This is a behavioral branch easy to lose in J2K; it must be preserved exactly and is pinned by two characterization tests (speed-is-global → GLOBAL; speed-set → stored value). Kotlin `feedPlaybackSpeed == SPEED_USE_GLOBAL` (`Float` structural equality) reproduces the Java `float ==`.
- **API preservation (per `model/README.md`, carried forward — no `data class`).** All three classes keep their exact current Java surface, plain `class`/`enum class`, never `data class`:
  - `EmbeddedChapterImage` → plain `class`; constructor `(Playable?, String)`, `getPosition`/`getLength`/`getMedia` accessors, `@JvmStatic fun makeUrl(Int, Int): String` and `@JvmStatic fun getModelFor(Playable, Int): Any` (**preserve the `Object`/`Any` polymorphic return** — instance or raw `String` — and the `IllegalArgumentException` throw); hand-written `equals`/`hashCode` on `imageUrl` only. Not `Serializable` → **no** `serialVersionUID`.
