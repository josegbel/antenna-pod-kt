## Research findings that change the task's shape
- **Line 659 confirmed unchanged.** `DBReader.getFeed`'s `@Nullable` is a genuine, documented invariant (`DBReader.java:321-353`) and must **not** be tightened — 9 of 15 production call sites already guard it.
- **CORRECTION 1 — the prior diagnosis was wrong that there is no `onError` handler.** One exists at `FeedItemlistFragment.java:676-683` and already handles the null-feed case gracefully. The crash is specifically RxJava's **disposed-subscriber** branch bypassing it.
- **CORRECTION 2 — severity overstated.** `RxJavaErrorHandlerSetup.java:16-36` (installed at `PodcastApp.java:19`) swallows this exact exception class; it only rethrows under `if (BuildConfig.DEBUG)` (`:31-34`). **Release builds do not crash.** They write a phantom `crash-report.log` that AntennaPod shows the user in its Bug Report screen (`BugReportViewModel.java:66-67`). PR wording must not say "fixes a production crash" — flagged for José (OQ / Unknown 4).
- **A naive null guard at `:659` alone is a REGRESSION.** The success consumer reads the `feed` *field*, not `result.first` (`:666,667,671`); guarding only the callable makes it NPE on the **main thread**, which crashes in every build type. The fix must address both ends.
- **Production trigger confirmed real** (softening not needed on this point): `MainActivity.loadChildFragment` uses `.hide().add()` not `replace`, so a hidden `FeedItemlistFragment` stays EventBus-registered and `onQueueChanged`/`onPlayerStatusChanged` re-trigger `loadItems()` unconditionally; feeds vanish via `SyncService.kt:164` (cross-device unsubscribe) and `FeedUpdateWorker.java:115` → `NonSubscribedFeedsCleaner`.
- **Test trigger pinned deterministically:** JUnit `MethodSorters.DEFAULT` hash ordering puts `testExistingMedia` immediately before `testExistingNonSubscribedFeed`, and `testExistingMedia` is what opens the stale `FeedItemlistFragment`.
- **Zero test coverage of `FeedItemlistFragment`** of any kind — no JVM test, no targeted instrumented test. `:app` has Robolectric 4.16 but **no** `fragment-testing`/`FragmentScenario`.
- **Static analysis structurally cannot catch this:** `config/spotbugs/exclude.xml:250` globally suppresses `NP_NULL_ON_SOME_PATH_FROM_RETURN_VALUE` (upstream, ByteHamster 2021-03-27). Out of scope to change.
- **New CI evidence:** run `31796405935` reports `Emulator Test API 30` as **`success`** while its log contains a full signature-matched crash.
