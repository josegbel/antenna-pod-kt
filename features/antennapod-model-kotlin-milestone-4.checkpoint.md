## Red-team plan outcome (2026-07-22, Loop 1 of 2 — CHALLENGE)
- **CRITICAL:** The plan's Resolved-Decision justification for `FeedFunding`'s split fix — "Kotlin's `Regex`-overload delegates to `Pattern.split(..., 0)`, preserving the trailing-strip" — is **factually wrong**, verified by decompiling `kotlin-stdlib-2.0.21.jar`'s `kotlin/text/Regex.split` (no trailing-strip logic at all) and by a runtime experiment. `.split(SEPARATOR.toRegex())` will **not** reproduce Java's `String.split(String)` trailing-empty-token stripping. Concretely: `extractPaymentLinks(payLinks)` where `payLinks` is just the separator character returns `null` in Java today (hits the `list.length == 0` guard) but would return an **empty non-null `ArrayList`** under the plan's translation — a real, observable divergence.
- **MAJOR:** Compounding this, the plan's own named proof test (`extractPaymentLinksTrailingSeparatorMatchesJava`) would not have caught this — traced by hand and confirmed experimentally that the existing `isBlank(linkContent[0])` guard absorbs the divergence for "content + trailing separator" inputs; only a payLinks-is-solely-separator-characters test surfaces it, and that test isn't in Step 3's list.
- **MINOR:** Step 5's `serializationDropsTransientFeedAndChapters` test should explicitly pin `media`/`transcript` to `null` in its fixture to avoid an accidental Tier C (`FeedMedia`/Android-framework-typed field) dependency leaking into a bare-JVM Tier A test.
